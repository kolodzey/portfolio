# Angular 20 Migration Summary

Migration date: 2026-09-26

## Outcome

The portfolio was upgraded from Angular 19 to Angular 20 using Angular's official CLI update tooling:

```text
npx ng update @angular/core@20 @angular/cli@20 --allow-dirty
```

The `--allow-dirty` flag was required because the completed Angular 18-to-19 migration was already present but uncommitted. The update stopped at Angular 20. Angular 21 was not installed, and no redesign, refactor, SSR, signals, zoneless change detection, or control-flow conversion was performed.

## Validation

- Clean installation: `npm ci` passed and installed 975 packages.
- Strict TypeScript compilation: `npx tsc -p tsconfig.app.json --noEmit` passed with no errors. The inherited configuration has `strict: true` and strict Angular template checks enabled.
- Production build: `npm run build` passed in 3.352 seconds. The initial bundle is 406.52 kB raw and 113.24 kB estimated transfer size; output is in `dist`.

The production build's native worker exited with code 134 inside the restricted filesystem sandbox. The identical command completed normally outside that sandbox without any project or configuration changes, confirming an execution-environment limitation rather than an application build error.

## Files changed by the Angular 19-to-20 migration

- `package.json`: Angular framework, CLI, build tooling, compiler CLI, and TypeScript versions were updated by the CLI.
- `package-lock.json`: the resolved Angular 20 dependency tree was generated by the CLI/npm.
- `angular.json`: the required CLI migration added workspace schematic naming defaults so newly generated artifacts retain the project's previous suffix conventions.

No application source, template, or style files were changed by the Angular 19-to-20 migration. The many already-modified component files in the worktree belong to the preceding Angular 18-to-19 migration, which removed redundant `standalone: true` declarations after standalone became the default.

This report file was manually updated after validation; it is not a CLI migration output.

## Required migrations that made no source changes

The Angular CLI checked these required migrations and found no applicable application code:

- Move `DOCUMENT` imports from `@angular/common` to `@angular/core`.
- Replace deprecated `InjectFlags` usage.
- Replace deprecated `TestBed.get` with `TestBed.inject`.
- Add `BootstrapContext` to server bootstrap calls.
- Move server-rendering imports and update server routing APIs.
- Change TypeScript `moduleResolution` to `bundler` (already configured).
- Remove default-only Karma configuration files (none present).

## Optional migrations intentionally skipped

- Application build-system migration.
- Template control-flow syntax migration.
- `Router.getCurrentNavigation` to signal-based navigation migration.

These were outside the requested compatibility-only scope. The project already uses the application builder, but the optional migration was still left unselected rather than allowing unrelated configuration rewriting.

## Deprecation warnings

`npm ci` reported:

- Direct runtime dependencies: `@angular/animations@20.3.32` and `@angular/platform-browser-dynamic@20.3.32`. Angular now recommends newer alternatives, but both packages were retained because replacing their APIs would be an optional application modernization and could change behavior.
- Transitive build/test dependencies: `inflight@1.0.6`, `rimraf@3.0.2`, `glob@7.2.3`, and `uuid@8.3.2`. They are not directly declared by the application and were not overridden outside Angular's supported dependency tree.

## npm advisories

The full development-tree audit reports 19 vulnerable packages: 1 low, 7 moderate, 11 high, and 0 critical.

- Direct dependency: `@angular-devkit/build-angular` (moderate). It is a development-only build dependency; npm's offered replacement is Angular build tooling 22.2.0, which is outside this migration's Angular 20 limit.
- Transitive build/test dependencies: 18 packages under Angular build tooling, Karma, or Karma Coverage (`@angular-devkit/build-webpack`, `brace-expansion`, `engine.io`, `fast-uri`, `flatted`, `follow-redirects`, `js-yaml`, `lodash`, `minimatch`, `picomatch`, `postcss-selector-parser`, `socket.io-adapter`, `socket.io-parser`, `sockjs`, `tmp`, `uuid`, `webpack-dev-server`, and `ws`).
- Production dependency audit: `npm audit --omit=dev` reports 0 vulnerabilities.

No `npm audit fix`, forced major upgrade, override, or Angular 21/22 update was applied.

## Manual application changes

None. All Angular 20 project changes were produced by the Angular CLI, and application behavior and styling were left untouched.
